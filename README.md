# Poker IQ 🃏

משחק אימון שמלמד לקבל את ההחלטה הנכונה בכל יד פוקר: פולד, צ׳ק, קול או רייז.
בלי כסף אמיתי ובלי הימורים. זה משחק לימודי.

## מה יש במשחק
- **מסע:** 7 עולמות × 3 שלבים, כוכבים ו-10 רמות. מתחילים מ"כולם ויתרו, נכנסים או לא?" ומגיעים עד 3-בט, צ׳ק-רייז ושעון.
- **8 סוגי סיטואציות** בכל 6 העמדות בשולחן (UTG, HJ, CO, BTN, SB, BB): פתיחה, מול העלאה, ביג בליינד מול לימפים, מול 3-בט, סי-בט, פעולה ראשונה בלי מיקום, מול הימור, ומול צ׳ק-רייז. הסיטואציות מגיעות בפרה-פלופ, פלופ, טרן וריבר.
- **הסבר במילים פשוטות אחרי כל החלטה:** מה קרה ביד, למה הפעולה הנכונה נכונה, ואיפה הייתה הטעות. אפשר ללחוץ על כל מושג (לימפ, אאוטים, מיקום…) ולקבל הסבר. המספרים המדויקים נמצאים בחלק "למתקדמים".
- **מילון** עם יותר מ-45 מושגים.
- **אתגר יומי:** אותן 10 ידיים לכולם, רצף ימים, ושיתוף התוצאה בוואטסאפ.
- **ראש בראש בזמן אמת:** יוצרים חדר, שולחים קישור בוואטסאפ, והחבר נכנס מהדפדפן בלי להתקין כלום.
- **דירוג:** לפי ניקוד כולל, לפי האתגר היומי ולפי ניצחונות.

## איך המאמן מחליט
1. **אקוויטי:** סימולציית מונטה קרלו של אלפי ידיים. היריבים מחזיקים טווח ידיים מציאותי: מי שהעלה מעמדה מוקדמת חזק יותר, ומי שמהמר אחרי הפלופ צריך לפגוע בשולחן.
2. **סיכויי קופה:** כמה צריך לנצח כדי שקריאה תשתלם.
3. **מיקום:** מי שפועל ראשון מממש פחות מהיד שלו.
4. **ספי העלאה** שיורדים ככל שיש יותר יריבים. כשההחלטה על הגבול, שתי תשובות מקבלות ניקוד.

זה מודל לימודי, לא סולבר. הוא לא מתחשב בגודל ערימות או בסגנון של יריב מסוים.

## טכנולוגיה
- React + TypeScript + Vite, אנימציות עם framer-motion.
- Supabase: טבלת `poker_players` (הדירוג) ופונקציות `poker_save_player` / `poker_record_match`. חדרי ראש בראש עובדים על Supabase Realtime (broadcast + presence).
- Capacitor: עוטף את המשחק לאפליקציה לאייפון (`ios/`) ולאנדרואיד (`android/`).

מחברים את הריפו ל-Vercel. ההגדרות כבר קיימות ב-`vercel.json`. אחרי שיש כתובת, מגדירים אותה ב-Vercel כ-`VITE_PUBLIC_URL`, כדי שקישורי ההזמנה בוואטסאפ יצביעו עליה.

## העלאה לחנויות
**חשבונות שצריך:** Apple Developer (‏99$ לשנה) ו-Google Play Console (‏25$ חד-פעמי).

לפני ההעלאה הראשונה, משנים את `appId` ב-`capacitor.config.ts` (כרגע `com.pokeriq.app`) למזהה ייחודי משלך.

```bash
npm run build && npx cap sync      # מעתיק את המשחק לפרויקטים של iOS ו-Android
```

- **Android:** פותחים את `android/` ב-Android Studio ← Build ← Generate Signed Bundle ← מעלים את ה-‎.aab ל-Play Console.
- **iOS עם Mac:** מריצים `npx cap open ios`, ב-Xcode בוחרים Team ← Product ← Archive ← מעלים ל-App Store Connect.
- **iOS בלי Mac:** שירות ענן כמו Codemagic בונה ומעלה מהריפו (צריך לחבר את חשבון ה-Apple Developer).

**מדיניות החנויות:** משחקי פוקר בלי כסף אמיתי מותרים, אבל מסווגים כ"הימורים מדומים". באפל הדירוג יהיה כנראה ‎17+‎, ובגוגל צריך לסמן את זה בשאלון התוכן. אסור להוסיף אפשרות לזכות או לקנות כסף אמיתי.

## המאמן החכם (AI)
השרת `supabase/functions/poker-coach` כבר פרוס ב-Supabase. כדי להפעיל אותו:
1. ב-Supabase: Project → Edge Functions → Secrets.
2. מוסיפים `OPENROUTER_API_KEY` עם המפתח מ-openrouter.ai. **לא שמים אותו בקוד ולא באפליקציה.**
3. אופציונלי: `OPENROUTER_MODEL` (כל מזהה מודל של OpenRouter; ברירת המחדל בקוד היא `google/gemini-2.5-flash`, כדאי לוודא שהוא זמין בחשבון), ו-`COACH_DAILY_LIMIT` (שאלות ליום לשחקן, ברירת מחדל 15).

## מדידה לניסוי החברתי
כל האירועים נשמרים בטבלה `poker_events`: כניסה, הרשמה, סיום שלב, אתגר יומי, קרבות ושאלות למאמן. רשימת ההמתנה ל-Pro, כולל המחיר שכל שחקן ראה, נשמרת ב-`poker_waitlist`. שאילתות שימושיות:
```sql
-- כמה שחקנים חזרו ביום אחר מהיום הראשון שלהם
select count(*) from (select player_id, count(distinct created_at::date) d from poker_events where event='app_open' group by 1) x where d > 1;
-- כמה נרשמו ל-Pro לפי מסלול ומחיר
select tier, price_seen, count(*) from poker_waitlist group by 1,2 order by 1,2;
```

## שולחן חברים — השלמת ענף table-wip

- מצבים מוכנים: רגיל (בליינדים קבועים), טורבו (5 דקות ותור של 20 שניות), טורניר (10 דקות וללא ריביי). ההגדרות ניתנות לשינוי לפני פתיחת החדר.
- שולחן עם רקע חדר, שולחן ודילר גבר בנכסים נפרדים. ממשק פעולות קריא, מותאם גם למסך אופקי.
- החזקה בעכבר, מגע, רווח או Enter מציצה בפינות הקלפים. שחרור, איבוד מיקוד או מעבר לחלון אחר מסתירים אותם.
- שולחן אימון מול חמישה בוטים בסיסיים, מסומן בבירור ואינו מתחבר לחדרי החברים.
- כללי העלאה לאחר אול־אין חלקי: שחקן שכבר פעל אינו מקבל רייז מחדש בלי עלייה מלאה. נבדקים גם תורות heads-up, פעולות שגויות, הפסקה, פרטיות הקלפים וסך הז׳יטונים.

בדיקות:
```bash
npm run build
npm run test:table
npm run test:engine
```

`test:table` מריץ בדיקות מקרי קצה ועוד 400 משחקים מדומים דטרמיניסטיים. בבדיקת רשת נפרדת אומתו פתיחת חדר אמיתי, הצטרפות לקוח נוסף, קבלת שני קלפים מוצפנים, פעולת אורח והשלמת יד עד חשיפת הקלפים.

הגבלות נוכחיות: המנהל מריץ את המשחק במכשיר שלו וחייב להישאר מחובר. ההצפנה הקיימת אינה הופכת אותו לשרת סמכותי או מונעת רמאות מצד המנהל. הז׳יטונים הם של החדר; ארנק מתמשך בין חדרים וגלגל בונוס יומי עדיין אינם ממומשים. אין כסף אמיתי או אפשרות פדיון.

### התאמה לתמונת הייחוס

החדר מצויר על קנבס 1672×941 עם שינוי קנה מידה אחיד. שולחן, רקע, דילר, דיוקנאות ויד הם נכסים נפרדים; הנתונים והפעולות נשארים רכיבים חיים. תנועת היד, פינות הקלפים, חלוקת הקלפים ותנועת הצ׳יפים מונפשות בנפרד. זהו ממשק דו־ממדי בשכבות עם פרספקטיבה (2.5D), לא מודל תלת־ממדי של המקור ולא התאמה פיקסלית מובטחת. לטלפון מומלצת תצוגה אופקית; במצב אנכי נשמר היחס ומוצגת הודעת סיבוב.
